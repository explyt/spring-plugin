Reports a configuration value that is not written in the spelling Spring itself recommends, and offers a quick-fix that rewrites it.

Two sources say what that spelling is. A metadata hint states the accepted literals verbatim, and every literal Spring ships is lower case, so logging.level.root=INFO is written against the metadata that declares info. For an enum-typed value the recommended form is lower case with - between words: Spring's own metadata never uses the declared SCREAMING_SNAKE name as a default value — on spring-boot-autoconfigure-3.5.13 all enum-typed properties with a string defaultValue spell it in lower case (never, graceful) or kebab-case (read-uncommitted, path-pattern-parser).

Spring's relaxed binding accepts every spelling, so this is a style report rather than an error.

Examples:


logging.level.root=INFO                           # -> info
management.endpoint.conditions.access=READ_ONLY   # -> read-only
management.httpexchanges.recording.include=REQUEST_HEADERS,response_headers
                                                  # -> request-headers,response-headers

The inspection does not report:

  • a value matching neither a hint literal nor an enum constant — it is either free-form, such as a hint whose provider is any, or a genuine error reported by a separate diagnostic;
  • a value containing a ${...} placeholder, which is resolved at runtime.
