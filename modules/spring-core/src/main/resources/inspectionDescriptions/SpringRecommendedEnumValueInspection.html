Reports a configuration value that resolves to an enum constant but is not written in the spelling Spring itself recommends — lower case with - between words — and offers a quick-fix that rewrites it.

Spring's relaxed binding accepts the declared SCREAMING_SNAKE name too, so this is a style report. Spring's own configuration metadata, however, never uses that form for a default value: on spring-boot-autoconfigure-3.5.13 all enum-typed properties with a string defaultValue spell it in lower case (never, graceful) or kebab-case (read-uncommitted, path-pattern-parser).

Examples:


management.endpoint.conditions.access=READ_ONLY   # -> read-only
management.httpexchanges.recording.include=REQUEST_HEADERS,response_headers
                                                  # -> request-headers,response-headers

The inspection does not report:

  • a value that does not resolve to an enum constant — that is a separate diagnostic;
  • a value backed by metadata hints, such as logging.level.root=INFO, because those literals come from metadata already written in the spelling users type;
  • a value containing a ${...} placeholder, which is resolved at runtime.
