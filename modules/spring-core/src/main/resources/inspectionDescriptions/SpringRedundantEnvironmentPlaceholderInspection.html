Reports a single environment-variable placeholder whose name repeats the relaxed-binding environment form of the full property key. For ordinary configuration keys, Spring Boot can read that environment variable without the placeholder.

Bootstrap and profile-selection keys are excluded: spring.config.import, spring.config.activate.on-profile, spring.config.activate.on-cloud-platform, spring.config.location, spring.config.additional-location, spring.config.name, spring.profiles.active, spring.profiles.include and spring.profiles.group (including its entries).

The quick fix replaces the placeholder with a simple literal default and is available in Code Cleanup. No fix is offered without a default, with a nested placeholder or SpEL expression such as #{null}, or with backslashes or a leading = or : in a .properties default.

In YAML, a nonempty default must contain only ASCII letters, digits, or ._/@+- and cannot start with -, +, or @. Defaults with spaces, quotes, colons or hash signs are left unchanged, as are YAML boolean and null spellings (in any case, including ~) and special numeric forms such as 0x10.

Limitations:

  • Unquoted decimal YAML defaults remain eligible for the fix. An Object or Map<String, Object> binding may then receive a number (for example, an Integer or Double) instead of a String.
  • A JVM system property with the same name as the environment variable (for example -DEXPLYT_VALUE=override) can override the environment variable when resolving an explicit placeholder. Removing the placeholder may bypass that override.
  • The inspection checks any YAML or properties file that the plugin recognizes as Spring configuration, including files under config/ that Spring Boot does not load by default.
