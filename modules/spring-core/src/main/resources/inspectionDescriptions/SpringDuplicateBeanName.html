Reports a @Bean method whose bean name is already declared by a differently named @Bean method of the same configuration class.

Spring Boot disallows bean definition overriding by default, so such a configuration fails at startup with BeanDefinitionOverrideException. Overloaded @Bean methods with the same method name are merged by Spring and are not reported.

When spring.main.allow-bean-definition-overriding=true is set in the module configuration, nothing is reported before Spring Framework 7, for a lite class such as a @Component with @Bean methods, or for a @Configuration(enforceUniqueMethods = false) class, also when enforceUniqueMethods is set through a composed annotation. Spring Framework 7 fails at startup for any other @Configuration class whatever the property says, so the problem is always an error there, and it is reported as a warning when the property allows overriding but the Spring Framework version cannot be determined.

Methods annotated with @Profile or another @Conditional annotation, such as @ConditionalOnProperty, are not reported: Spring evaluates their conditions before it registers the bean name, so only one of them may be active.

When the value of spring.main.allow-bean-definition-overriding cannot be resolved, for example because it is a placeholder or depends on a profile, the problem is reported as a warning instead of an error, except for a @Configuration class on Spring Framework 7, which fails whatever the value is.
