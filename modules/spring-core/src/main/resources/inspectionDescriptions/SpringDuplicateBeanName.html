Reports a @Bean method whose bean name is already declared by a differently named @Bean method of the same configuration class.

Spring Boot disallows bean definition overriding by default, so on Spring Framework 6.2.0 and later such a configuration fails at startup with BeanDefinitionOverrideException. Overloaded @Bean methods with the same method name are merged by Spring and are not reported.

When the shared name is the primary bean name of both methods, that is the first name declared in @Bean, or the method name when none is declared, Spring Framework before 6.2.0 starts with such a configuration whatever spring.main.allow-bean-definition-overriding says and silently ignores one of the two methods, so the problem is reported there as a warning, for @Configuration and lite classes alike. Which method is kept cannot be told from the source order. A name that is an alias of at least one of the methods, that is a name declared after the first one in @Bean, fails at startup on every Spring Framework version unless bean definition overriding is allowed. When the Spring Framework version cannot be determined and overriding is not allowed, a collision of primary names is reported as a warning that names both outcomes.

When spring.main.allow-bean-definition-overriding=true is set in the module configuration, nothing is reported on Spring Framework 6.2.x, for a lite class such as a @Component with @Bean methods, or for a @Configuration(enforceUniqueMethods = false) class, also when enforceUniqueMethods is set through a composed annotation. Spring Framework 7 fails at startup for any other @Configuration class whatever the property says, so the problem is always an error there, and it is reported as a warning when the property allows overriding but the Spring Framework version cannot be determined.

Methods annotated with @Profile or another @Conditional annotation, such as @ConditionalOnProperty, are not reported: Spring evaluates their conditions before it registers the bean name, so only one of them may be active.

When the value of spring.main.allow-bean-definition-overriding cannot be resolved, for example because it is a placeholder or depends on a profile, the problem is reported as a warning instead of an error, except for a @Configuration class on Spring Framework 7, which fails whatever the value is.
