Reports a @Bean method whose bean name is already declared by a differently named @Bean method of the same configuration class.

Spring Boot disallows bean definition overriding by default, so on Spring Framework 6.2.0 and later such a configuration fails at startup with BeanDefinitionOverrideException. Overloaded @Bean methods with the same method name are merged by Spring and are not reported.

When the shared name is the primary bean name of both methods, that is the first name declared in @Bean, or the method name when none is declared, Spring Framework before 6.2.0 starts with such a configuration whatever spring.main.allow-bean-definition-overriding says and silently ignores one of the two methods, so the problem is reported there as a warning, for @Configuration and lite classes alike. Which method is kept cannot be told from the source order. When the Spring Framework version cannot be determined and overriding is not allowed, a collision of primary names is reported as a warning that names both outcomes.

A name declared after the first one in @Bean is an alias. Unless bean definition overriding is allowed, an alias shared by both methods fails at startup on every Spring Framework version. A name that is the primary bean name of one method and an alias of the other fails at startup from Spring Framework 6.0; before 6.0 the outcome depends on the order Spring registers the two methods: it fails at startup or silently ignores one of them, so the problem is reported there as a warning, as it is when the Spring Framework version cannot be determined. Such alias collisions fail with BeanDefinitionOverrideException or IllegalStateException.

When spring.main.allow-bean-definition-overriding=true is set in the module configuration, an alias collision is not reported, and neither is a collision of primary names on Spring Framework 6.2.x, for a lite class such as a @Component with @Bean methods, or for a @Configuration(enforceUniqueMethods = false) class, also when enforceUniqueMethods is set through a composed annotation. For a collision of primary names Spring Framework 7 fails at startup in any other @Configuration class whatever the property says, so the problem is always an error there, and it is reported as a warning when the property allows overriding but the Spring Framework version cannot be determined.

Methods annotated with @Profile or another @Conditional annotation, such as @ConditionalOnProperty, are not reported: Spring evaluates their conditions before it registers the bean name, so only one of them may be active.

When the value of spring.main.allow-bean-definition-overriding cannot be resolved, for example because it is a placeholder or depends on a profile, an error is reported as a warning that says so, except for a collision of primary names in a @Configuration class on Spring Framework 7, which fails whatever the value is. A warning about a Spring Framework version before 6.2.0 or before 6.0, or a version that cannot be determined, is kept as it is.
