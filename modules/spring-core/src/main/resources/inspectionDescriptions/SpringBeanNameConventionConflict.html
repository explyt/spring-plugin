Reports a composed @Bean annotation whose name attribute, set at the use site, conflicts with the name fixed by the meta @Bean("...") value.

On Spring Framework 6 an annotation attribute called name without an @AliasFor to @Bean overrides @Bean.name by convention. When the meta-annotation fixes the bean name through value and the use site sets a different name, the application fails at startup with AnnotationConfigurationException: Different @AliasFor mirror values.

Not reported: Spring Framework 7, which no longer applies convention-based overrides; an unknown Spring version; attributes declared with an explicit @AliasFor to @Bean; a meta @Bean(name = "..."), which the convention simply overrides; a use site that leaves name at its default or sets it to the meta value.

Example:


    @Bean("fixed")
    @Retention(RetentionPolicy.RUNTIME)
    @interface MyBean {
        String[] name() default {};
    }

    @Configuration
    class AppConfiguration {
        @MyBean(name = "x")
        Foo foo() { return new Foo(); }
    }
