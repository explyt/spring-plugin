Reports a @Controller or @RestController value that contains /. The value is the bean name, not a request path: no path prefix is applied to the handler methods.

On Spring MVC a value starting with / is also registered by BeanNameUrlHandlerMapping: a request to exactly that path that no request mapping handles fails with HTTP 500, because no handler adapter supports an annotated controller.

Classes implementing HttpRequestHandler or org.springframework.web.servlet.mvc.Controller are not reported: their bean name is their URL.

Quick fixes:

  • Move to @RequestMapping - when neither the class nor its superclasses and interfaces declare a type-level @RequestMapping, directly or through a composed annotation.
  • Remove bean name - otherwise; the existing type-level mapping stays unchanged.

Example:


    @RestController("/app")
    class AppController {
    }
